Имя продукта, репозитория и namespaces: **duskOfEmpire** (не TechnoShooter).

---

## 1. High Concept

Техномагический постапокалиптический top-down шутер с ограниченным восприятием. Игрок видит только текущий сектор обзора; всё остальное — «память», которая размывается, искажается и наполняется фантомами. PvPvE про охоту, шум и гонку за целями.

## 2. Pillars (приоритет ощущения среза)

Главное ощущение вертикального среза:

1. **Шум приводит к смерти**
2. **Верить можно только своей памяти** (правда — только в текущем секторе)

Остальные pillars без изменений по смыслу: восприятие как ресурс; кооперативная охота (Darkwood + Hunt + Alien Swarm); техномагия; никакой «честности» памяти вне сектора.

## 3. Core Loop (PvPvE)

Заспавнился → собрал лут → двинулся к точке, управляя шумом → пережил орду / схлестнулся с врагами → прошёл цепочку из 3 точек → победил.

### Objectives (LOCKED)

- Точки **общие**.
- Саботаж чужой/оспариваемой точки — **можно и нужно**.
- Орды **2 / 2 / 3** — триггер на **начало захвата** точки.
- Вечный пуш ордой у финиша **ничем не останавливается**: игроки должны страдать. Баланс страдания — через геймплей (шум, позиция, классы), не через «выключатель орды».

## 4. Восприятие и память (LOCKED)

### Правило истины

- Текущий сектор = истина. В секторе нет искажений, фантомов, ложного лута.
- Вне сектора = память. Может искажаться.
- Взаимодействовать с памятью как с реальностью нельзя на сервере: проверка истины — только поворот взгляда.
- Стрельба только в текущий сектор.
- Память каждого — **своя и независимая** (в т.ч. при 2–4 игроках на LAN).

### Союзники вне сектора

- Цветное пятно = **только факт присутствия**.
- Без класса, HP, направления, статуса.

### Стадии размытия

Константы в `config.json` (как в v1.0): чётко → лёгкое → сильное → силуэт → исчезло (0–15 / 15–30 / 30–45 / 45–55 / 55–60 с). Модификатор класса ±20 с. Повторный взгляд обновляет запись мгновенно.

### Визуал памяти (LOCKED)

- Не «фото-blur всего кадра», а **фильтр (туман / засеревание / размытие в духе Darkwood)**, накладываемый на **каркас карты** (геометрия/маска исследованного и устаревшего).
- Ложная память визуально не отличается от обычной памяти.

### Фантомы (клиентские) (LOCKED)

- Только на клиенте, не в ECS сервера.
- Визуально неотличимы от правды.
- Могут **изображать** всё поведение того, что искажают (дойти, замахнуться, «выстрелить»).
- **Реального воздействия нет**: удар фантома — no-op; сервер их не симулирует.
- При попадании в текущий сектор уничтожаются в том же кадре.

## 5. Камера и управление

- Top-down ortho, стиль Darkwood.
- Поворот персонажа за мышью.
- Сектор привязан к прицелу, инерция поворота.
- Стойка = широкий короткий сектор; прицел = узкий длинный.

## 6. Персонажи — вертикальный срез (LOCKED)

В срезе **2 класса**:

| Класс | Фантазия | Черты |
| --- | --- | --- |
| Танк | фронт / давление | дробовик |
| Базовый стрелок | утилита / темп | скилл: создать **один случайный расходник** раз в **30 с** |

На релиз — 6–7 классов. Мета-прогрессия — только скины.

## 7. Экипировка и инвентарь (LOCKED)

- 7 слотов: голова, тело, руки, обувь, основное, второстепенное, расходник (один).
- Бесконечный пул патронов, ограниченный магазин → перезарядка = темп.
- Ближний бой не отдельный слот; пинок всегда доступен.
- Крафта и общего склада нет.
- При смерти в PvPvE выпадает всё.

### Пинок (LOCKED)

- Всегда доступен.
- Базово: **минимальный урон**.
- Почти не двигает крупные объекты (Зверь, шкаф и т.п.).
- Роль: emergency-touch / добивание мелочи, не CC-танк-инструмент.

## 8. Оружие и стихии

Без изменений по списку v1.0. Снаряды-росчерки + серверный hitscan с лаг-компенсацией. Стихии без кросс-взаимодействий в срезе.

## 9. Лут (LOCKED)

- Лут на карте **фиксируется при генерации** (в срезе — при загрузке/подготовке `map` session loot table). Нет бесконечного роста качества/количества со временем сессии.
- Самый сильный лут: **наибольший шанс** выпадения в окне **последние 10 минут до конца** и до окончания.
- Расходники с мобов: частота выпадения **равномерная**, редкость — **смещена по времени** (лучше к концу).
- Выпавший на землю лут **очищается раз в 5 минут**.
- Snowball есть, но ограничен пулом и окном редкости, не бесконечным эскалированием.

## 10. Конструкции и шум

Как в v1.0. Шум — оружие и уязвимость; индикатор направления + размера.

## 11. Уровни

- Одноуровневые; в срезе — зафиксированная сцена.
- Двери разрушаемы, стены — нет.
- Освещение **влияет на механику движка** (закладывается с Phase 0; геймплейное использование наращивается позже).

## 12. NPC

Все типы из v1.0 желательны в срезе как можно раньше (приоритет скорости покрытия, не «отрезать до конца»). Константы Роженицы / Загонщика — из конфига.

## 13. Смерть и здоровье

Как в v1.0. PvPvE: респавн из зоны через 30 с. Friendly fire: 10% + штраф очков.

## 14. Режимы

| Режим | Игроков | Формат |
| --- | --- | --- |
| PvPvE (первый) | до 10 (5×5 или FFA) | цепочка из 3 общих точек, орды 2/2/3 на старт захвата, саботаж |
| PvP | до 10 | DM / элиминация / кейс |
| PvE-кампания | 1–5 | сюжет |

Мультиплеер среза: **LAN в одной комнате** (отдельные машины/инстансы по сети, не split-screen).

## 15. UI

- Кромка сектора = граница тумана памяти.
- Миникарта: **стилистика** «нарисованной от руки»; **содержимое** — исследованный маршрут (дорисовывается там, где игрок уже побывал).
- Индикаторы: шум, HP, скиллы, расходник, патроны в магазине.

## 16. Аудио и визуал

Low-poly 3D, top-down ortho. Звук критичен. Музыка: эмбиент → угроза → орда.

## 17. Технический стек (LOCKED)

| Слой | Решение |
| --- | --- |
| Framework | MonoGame 3.8.x DesktopGL |
| Runtime | .NET 8 LTS |
| ECS | Arch |
| Физика | Своя kinematic (AABB + sphere + spatial hash) |
| Сеть | LiteNetLib (LAN); архитектура host/client с Phase 0 |
| Сериализация | MemoryPack (снапшоты), System.Text.Json (config/map) |
| UI debug | MonoGame.ImGuiNet |
| Рендер | ручной ortho + HLSL; RT: scene, memory mask/view, **light** (задел с Phase 0) |

### Архитектурные locks (из ревью)

1. **Симуляция и отрисовка разделены с Phase 0** (`Sim` / `Render`, без `Render` внутри sim-систем).
2. **Host / Client разделены с Phase 0** (listen-host на LAN допустим, но код не смешивает «мир» и «картинку»).
3. **Тикрейт и авторитет** (наименее болезненно для сети):
   - фиксированный sim-tick **30 Hz** на хосте;
   - хост авторитетен для мира, NPC, hitscan, лута, objectives;
   - клиент: ввод, предикт локального движения, **локальная память/фантомы/свет для своего view**;
   - рендер клиентов может быть 60 FPS, интерполяция remote-сущностей.
4. **Память независима у каждого клиента** (свой mask/filter pipeline на view).
5. **Config**:
   - **матч-правила** (память, урон, FF, орды, лут-таймеры, скиллы) — задаёт хост, реплицирует клиентам, локальный hot-reload у клиента их не меняет в матче;
   - **клиентские** (громкость, чувствительность мыши, яркость, качество постэффектов) — локально, hot-reload ок;
   - вне матча (меню/редактор) — полный reload `config.json` для тюнинга.

## 18. План фаз

0 фундамент → 1 карта/физика → 2 игрок → 3 память → 4–5 враги → 6 оружие → 7 лут → 8 конструкции/шум → 9 PvPvE → 10 LAN-мультиплеер.

Врагов предпочтительно закрывать **как можно раньше** внутри 4–5, не откладывая «всех» на конец среза.

## 19. Скоуп среза

- 2 класса (танк-дробовик, стрелок с random-consumable 30 с).
- Одна карта «городская застройка», 3 общих objective.
- Все ключевые механики PvPvE + саботаж + орды без финального soft-stop.
- LAN 2–4 клиента.
- Монетизация на релиз: F2P + косметика. Команда: соло + ИИ.

## 20. Успех и риски

Успех: «шум = смерть», «правда только в секторе», читаемая охота.  
Режем в последнюю очередь: голос → часть polish NPC → уже отложенная процедурка.  
Не режем без крайней нужды: память, шум, общие саботируемые точки, независимую память клиентов.
